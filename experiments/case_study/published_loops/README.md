# Loop boundaries in published plans

This structural census uses the [6K-Set from Chowder](https://github.com/Texera/Chowder/tree/e054e86a6a239b15783b8884e675a5f43a36f38d/experiments/workflows/6k_set). Its archive SHA-256 is pinned in `analyze.py`. [Pasta §6.2 and Table 4](https://doi.org/10.1145/3698832) report 6,148 workflows for analysis, 849 for materialization-size evaluations, and two executable workflows for clock-time evaluations. [Chowder Table 2](https://github.com/Texera/Chowder/blob/e054e86a6a239b15783b8884e675a5f43a36f38d/Chowder_Full_Technical_Report.pdf) reports 6,191 plans for the planner and six end-to-end workflows. The [released Pasta archive](https://github.com/Texera/Pasta/blob/288f25009f10a142300a14bcfd85710be8c87adf/pasta_experiment_inputs/mat_size_experiment_workflows.zip) contains 6,191 JSON files. A multiset comparison of SHA-256 hashes matched all 6,191 JSON payloads to the Chowder archive, including entries with different filenames. We count this as one source.

The archived plans retain operator display names, port identifiers and edges. The two boundary nodes in each eligible plan substitute dummy operators for the original configurations.

Of 6,191 entries, 1,326 contained a directed path from a recognized start to a recognized end. We match normalized loop start/end labels and the exact names X-Partitioner and X-Aggregator. These nodes open and close a [cross-validation loop](https://www.knime.com/blog/predict-customer-churn-low-code-ml-example). The screen found 836 entries with one start and one end and 490 with additional boundaries. Recognizing the two names added 79 distinct structures and reclassified 28 previously single-pair structures as multi-boundary.

We fingerprint each labeled directed graph using the multisets of its labeled predecessors and successors recursively, including the source and target ports of every edge. Node IDs, filenames, display coordinates and edge ordering do not affect the fingerprint. Different fingerprints distinguish different labeled structures. We retained one entry per fingerprint and examined 1,198 distinct labeled structures. The 801 single-pair structures allow an unambiguous boundary-type and side-link comparison. For the remaining 397, we recorded the number of distinct labeled starts and ends and the number of reachable start/end combinations. Reachability alone cannot identify the matching end of a nested or sequential loop.

The census found 41 distinct pairs of normalized boundary labels. The original eight output-checked examples cover pairs present in 420 structures. The ninth example adds the recursive/recursive pair found in 64 more, bringing coverage by boundary type to 484. Sharing a boundary type does not verify the computation on that plan's inputs. In 468 structures outside edges to and from the start-to-end paths pass through the corresponding boundary. The other 333 contain a side link. Some lead to legal side sinks.

The [multi-boundary inventory](multiple.csv) supplies the other 397 fingerprints. The [boundary-count histogram](../../../figures/published-loop-boundaries.pdf) groups the 1,198 plans by their number of labeled starts plus ends. The [single-pair census](plans.csv) records fingerprints, boundary labels and side-link counts. Archive member names are represented by hashes. The old 500-structure sample is retained in [sample.csv](sample.csv) with its original eight-example coverage flag. The [reference pairs](reference_pairs.json) identify the [original eight](../sources.json) and the [targeted recursive example](../recursive/source.json). Label normalization retains port suffixes and deprecated labels and treats “TableRow” as “Table Row”.

The [bundled topology archive](topologies.tar.gz) retains all 6,191 graphs, including isolated operators and directed port connections. The projection replaces file names with their hashes and assigns integer IDs to operators within a plan. It keeps the operator labels and the flag for omitted source XML used by the census. To rebuild it from the upstream release, run `python project_archive.py plans_json.tar.gz topologies.tar.gz` with a new destination. The upstream release includes its [license](https://github.com/Texera/Chowder/blob/e054e86a6a239b15783b8884e675a5f43a36f38d/LICENSE) and [notice](https://github.com/Texera/Chowder/blob/e054e86a6a239b15783b8884e675a5f43a36f38d/NOTICE).

Use `python analyze.py topologies.tar.gz replay` for the offline census. To reproduce from the [pinned archive](https://raw.githubusercontent.com/Texera/Chowder/e054e86a6a239b15783b8884e675a5f43a36f38d/experiments/workflows/6k_set/plans_json.tar.gz), run:

```sh
python analyze.py plans_json.tar.gz replay
python -m unittest -v
```

The three generated files should match the committed CSV and JSON. These observations describe the archived graphs. Whole-workflow output comparisons use ten runnable examples separately. The tenth uses the same recursive boundary pair as the ninth, leaving the coverage of 484 structures unchanged.
